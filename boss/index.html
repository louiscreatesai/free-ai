BOSS: the rulebook that keeps your AI agents in line

What it is

When you run several AI agents on the same project, nobody tells them who owns what. One rewrites the file another just finished, and nobody checks the result.

The fix is one rulebook. It is a file of house rules that every agent reads before it touches anything, plus one lead agent that checks the work before it ships. In Claude Code the rulebook is a file called CLAUDE.md, and the lead agent is a subagent you define once.

1. Write the rulebook (five minutes)

  1. Open your project folder.
  2. Create a file named CLAUDE.md in the project root, or in a .claude folder inside it. Claude Code loads it at the start of every session. Subagents get it too, unless a subagent is set to skip it.
  3. Paste this and change it to fit your project:
# House rules

## Who owns what
- Agent 1 owns the front end: src/ui
- Agent 2 owns the backend: src/api
- Agent 3 owns the tests: tests/
- Agent 4 owns the docs: docs/
- Never edit a file that another agent owns. Ask the lead agent instead.

## Never do this
- Never delete or rename a file you did not create.
- Never rewrite a whole file when you only need to change a few lines.
- Never push or merge. Only the lead agent decides what ships.

## Before you say you are done
- Run the tests and write down what you ran.
- List every file you changed.

Keep the file short. The Claude Code docs suggest under 200 lines: longer files use more context and Claude follows them less closely.

2. Add the boss: a lead agent that checks the work

Create the file .claude/agents/lead.md in your project and paste this:

---
name: lead
description: Reviews the work of the other agents before anything ships. Use proactively when agents finish a task.
tools: Read, Glob, Grep, Bash
---

You are the lead agent. You do not write features. You check the work.

When you are called:
1. Read CLAUDE.md. These are the house rules.
2. Run git status and git diff to see every file that changed.
3. For each changed file, check that the agent that changed it owns it.
4. Check that nothing was deleted or renamed that should not have been.
5. Run the tests.

Then give me a short report: OK to ship, or BLOCKED, and for each problem the file, the rule it broke, and what to do.
Never fix things yourself. Never push or merge.

When your agents finish, ask Claude: "Have the lead agent review the changes." Claude can also hand the review to it on its own, because of the description line.

3. Use it

  1. Start your agents as usual. They all read CLAUDE.md at the start.
  2. When they finish, ask the lead agent to review.
  3. Fix anything it marks BLOCKED, then ask again.
  4. Whenever an agent breaks a rule, add a line to CLAUDE.md so it happens once at most.

Honest note

This is a guide, not a guarantee. The Claude Code docs say CLAUDE.md is context, not enforced configuration: an agent can still ignore a rule. If a rule must never be broken, such as deleting files or pushing code, the docs recommend a hook, which blocks the action whatever the agent decides. The lead agent also reads and runs checks, so it can miss things: look at what ships before you trust it. In the video the four agents deleting each other's work is a skit, not a real result.
