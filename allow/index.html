ALLOW

ALLOW: stop the Claude Code permission prompts without saying yes to everything, free

What it is

Claude Code asks permission before it runs commands, edits files or fetches the web. If you hit yes on everything without reading, you are not really approving anything. The fix is to decide once, in rules: allow the safe things, block the risky ones, and keep the prompts for the rest.

It is built into Claude Code. Nothing to install.

1. Open the rules

Type this inside Claude Code:

/permissions

It lists every rule and which settings file it comes from. You can add or remove rules there.

2. The three kinds of rule

  • Allow: Claude runs it without asking.
  • Ask: Claude always asks.
  • Deny: Claude cannot do it.

Deny is checked first, then ask, then allow. So a deny rule always wins over an allow rule.

3. Paste this into your settings

Put it in .claude/settings.json in your project (or ~/.claude/settings.json to apply everywhere):

{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git commit *)"
    ],
    "deny": [
      "Bash(git push *)"
    ]
  }
}

That runs your npm scripts and git commits without asking, and blocks any git push.

Put the * after the command you mean. Bash(git log *) allows only git log. Bash(git *) allows every git command, so be careful with that one.

4. The shortcut

When a prompt appears, choose "Yes, and don't ask again". For a command, Claude Code saves a rule so it stops asking for that command in that project. File edits are only remembered until the session ends.

5. Pick a mode instead

You can also change how Claude Code starts, with defaultMode in settings. acceptEdits approves file edits and simple file commands like mkdir and cp inside your project. plan makes Claude read and plan without editing.

Honest note

Do not use bypassPermissions unless you are in a throwaway container or virtual machine. It skips the prompts, including for the protected folders .git and .claude. Also, a rule is enforced by Claude Code itself, not by asking Claude nicely in your prompt, so rules are the safe way to do this.
